# brif-landing-page

Помощник, который заполняет бриф на лендинг вместе с тобой — задаёт вопросы по одному и не даёт оставить пустых пятен.

Обычный бриф разваливается не там, где его лень заполнять, а там, где заполнили формально: «повысить конверсию», «метрика — посещаемость», «дедлайн — как можно скорее». Исполнитель читает такое и всё равно приходит с вопросами, только уже через неделю. Здесь у каждого поля есть критерий «ответ засчитан»: расплывчатый ответ помощник не примет, переспросит один раз, а потом предложит две-три готовые формулировки на выбор. Всё, на что ответа нет вообще, попадает в реестр пробелов — с адресом, у кого спросить, и пометкой, блокирует это старт работ или нет.

**10–15 минут голосом, около 20 текстом.** Точечное изменение — минут пять.

---

## Шаг 1. Скачать папку

```bash
npx degit FortheHorde31/bcs/helpers/brif-landing-page brif-landing-page
```

Одна команда, скачается только эта папка. Если `npx` нет под рукой — нажми **Code → Download ZIP** на главной репозитория и достань из архива `helpers/brif-landing-page`.

Папку держи у себя: в ней не только инструкции, но и место, куда лягут твои брифы.

## Шаг 2. Впиши свою команду

Открой `CONTACTS.md` и подставь людей вместо *(имя)*. В репозитории лежит шаблон с ролями — он публичный, поэтому имён в нём нет.

Это не формальность. Когда человек говорит «я не знаю метрик», помощник не давит и не требует назвать ответственного — он сам подсказывает, у кого спросить. Без заполненного справочника подсказка выродится в «уточни у аналитика».

Полторы минуты один раз.

## Шаг 3. Запустить

Смотря чем пользуешься.

### Claude Code или Cursor

Открой скачанную папку как проект и просто скажи:

> собери бриф на лендинг

Всё. Если больше нравится командами — работают `/brif`, `/brif-check` (проверить готовый бриф) и `/brif-new` (подключить новый тип брифа).

Чтобы помощник был доступен из **любой** папки, а не только из этой, положи его в каталог агента:

```bash
cp -R brif-landing-page ~/.claude/skills/     # Claude Code
cp -R brif-landing-page ~/.codex/skills/      # Codex
```

### Cowork или claude.ai

Загрузи папку как скилл через интерфейс — там слэш-команд нет, и не нужно. Дальше просто скажи словами:

> собери бриф на лендинг
> помоги заполнить бриф на промо-страницу
> проверь мой бриф на пробелы

Помощник поймёт по описанию, что нужен именно он, и начнёт задавать вопросы. Переименовывать папку не надо — имя берётся из `SKILL.md`.

## Что произойдёт дальше

Помощник спросит, что делаем и для какого сайта, — и сразу скажет, сколько вопросов осталось: для новой страницы их около двадцати, для точечной правки шесть.

Дальше вопросы идут по одному. Расплывчатый ответ он не примет: скажет прямо, чего не хватает, переспросит один раз, а потом предложит две-три готовые формулировки на выбор. На вопросы, ответа на которые ты знать не обязан — метрики, цифры трафика, — разрешение не отвечать даётся сразу, вместе с самим вопросом, и переспрашивать он не станет.

Если положишь рядом материалы (страницу продукта, старый лендинг, выгрузку из Метрики) — предзаполнит из них что сможет и пометит источник у каждого значения.

Черновик сохраняется после каждого блока, так что прерваться можно в любой момент.

На выходе — один файл: заполненный бриф и реестр пробелов.

## Отвечать удобнее голосом

Бриф — это разговор, а не форма. Надиктованные ответы получаются подробнее, а помощнику нужна именно подробность: из «ну смотри, у нас люди приходят с рассылки и сразу отваливаются, потому что непонятно куда жать» он вытащит больше, чем из «повысить конверсию».

Варианты: голосовой ввод в самом агенте, системная диктовка macOS (двойное нажатие **Fn**), либо отдельные программы вроде Superwhisper или Wispr Flow — распознают точнее.

Сбивчивая речь, оговорки и отсутствие пунктуации не мешают: помощнику явно запрещено комментировать распознанную речь и поправлять формулировки. Он разбирает смысл и переспрашивает, если не понял.

## Что внутри

Три части, независимые друг от друга.

| Файл | Что делает |
|---|---|
| [`SKILL.md`](SKILL.md) | **Точка входа.** Роль, границы, режимы. Всё остальное подгружается по мере надобности |
| [`engine/INTERVIEW.md`](engine/INTERVIEW.md) | **Оболочка.** Как вести диалог, проверять ответы, обходиться с «не знаю», когда считать бриф готовым. Одна на все типы брифов |
| [`briefs/landing-page/`](briefs/landing-page/) | **Картридж.** Конкретные поля, условия показа, критерии зачёта, форма выхода |
| [`CONTACTS.md`](CONTACTS.md) | Справочник адресатов — заполняется под команду |
| [`engine/COMPILE.md`](engine/COMPILE.md) | Как собрать новый картридж из сырого шаблона |

Разделение не косметическое: движок и бриф меняются независимо. Правишь формулировку вопроса — трогаешь только картридж. Меняешь манеру интервью — только движок, и это отражается на всех брифах сразу.

## Свой тип брифа

Оболочка не привязана к лендингам. Положи любой сырой шаблон — анкету из Confluence, таблицу, список вопросов из переписки — и скажи «подключи новый тип брифа» (или `/brif-new`).

Помощник разберёт его на поля и допишет то, чего в сыром шаблоне почти никогда нет:

- **разобьёт склеенные вопросы.** «Как поймём, что задача решена? (метрика, дедлайн, ЛПР)» — это три разных ответа с тремя разными владельцами, вместе они всегда теряются
- **добавит каждому полю проверяемый критерий** зачёта вместо «ответ по существу»
- **пометит поля, ответа на которые заполняющий знать не обязан** — метрики, цифры трафика, экономика. Такие поля спрашиваются мягко, с разрешением не отвечать прямо в формулировке вопроса
- **найдёт вопросы, навязывающие форму решения.** «Какое целевое действие» подразумевает, что оно одно, — а страница может быть разводящей

Результат — новая папка `briefs/<название>/`, движок при этом не меняется.

## Правила, которые помощник не нарушает

- **Не заполняет бриф за человека.** Предлагать формулировки может, но только как варианты на выбор и с пометкой «предположение». Финальная формулировка всегда его
- **Не выдумывает факты.** Ставки, доходности, условия продуктов, цифры трафика — только из приложенных материалов или со слов человека. Каждое предзаполненное значение помечается источником
- **Не спорит о содержании задачи.** Сколько кнопок на странице, какая структура, нужен ли вообще лендинг — не его зона. Ответ «у нас так не устроено» считается ответом, а не уклонением
- **Не сохраняет файл без подтверждения**

## Что на выходе

Один файл: заполненный бриф плюс реестр пробелов.

Реестр — не список стыда, а рабочий инструмент. Бриф считается готовым **не когда все поля заполнены**, а когда по каждому незакрытому полю есть адресат и срок, и ни один блокер не остался без даты. Смысл не в идеальном документе, а в отсутствии пустых пятен, о которых никто не знает.

| Поле | Чего не хватает | У кого уточнить | Срок | Блокер |
|---|---|---|---|---|
| Метрика успеха | Целевое значение и источник данных | Аналитик площадки | старт работ | нет |
| Номер акции ЖЗ | Номер | Тот, кто заводит акции | 12.08 | да |

## Откуда взялась структура брифа

Поля собраны из рабочей анкеты команды сайтов БКС. Что при переносе изменилось — разбитые вопросы, ужесточённые и смягчённые критерии, добавленный блок про материалы и рамки — перечислено в конце [`briefs/landing-page/SPEC.md`](briefs/landing-page/SPEC.md), чтобы можно было сверить с оригиналом и откатить лишнее.
